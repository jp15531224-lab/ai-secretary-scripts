## 2. 問題点・設計上の注意（JPが気づきにくい点を含む）

1. **既存の画像ジョブとの干渉**：料理写真を今までどおり「AI取込み」メールに送ると、既存ジョブが「料理写真＝対象外」としてスキップログに残すだけ。
   → 食事用は**別の入口・別フォルダ**にする（既存ジョブからは見えない）。
2. **月別ハブへの混入**：既存の月別ハブは「`AI秘書` 配下で日付から始まるファイル」を全部一覧する。食事ノートを `AI秘書/` 配下に置くと**業務の月別一覧が食事記録で埋まる**。
   → 食事ノートは Vault 直下の `食事・健康管理/` に置き、`AI秘書/` と分離する。
3. **リアルタイム性**：Claude の定期ジョブは最短でも1時間ごと。「今日何カロリー？」に即答するには、**記録と集計を Make 側で即時に行う**必要がある。
4. **ボイスメモの日時**：Whisper Memos は録音日時を送らない（Makeの受信時刻のみ）。深夜の発言は日付判定がずれ得るので、**ボイスメモ由来は確認候補止まり**にする。
5. **「昨日」の意味**：午前1時に「昨日の夜ラーメン」と言った場合、6時区切りでは「昨日」が2通りに解釈できる。→ 6時区切りの「集計日」を基準に解釈し、**0〜6時の相対表現は確認候補**にする。
6. **外部AIへの送信**：写真・食事内容を Make 経由で OpenAI（または Anthropic）に送ることになる。健康関連情報なので、**送ってよいかの判断はJP**。
7. **推定精度の限界**：外食・会食の推定誤差は±20〜30%が普通。**単日の数字ではなく週平均で判断**する設計にする（ご依頼どおり）。

### 4-2. 食事DB（スプレッドシート）のシート構成

| シート | 主な列 | 役割 |
|---|---|---|
| 食事 | 品目ID（例 `M20261017-123015-a1b2-01`）、食事ID、状態（確定／仮／取消）、食べた日時、**集計日**、品名、数量・単位、食べた割合、kcal（下限・目安・上限）、食塩、たんぱく質、脂質、炭水化物、アルコールg、根拠（栄養表示／成分表／標準料理／写真推定／AI推定）、確信度（A〜D）、情報源、原本リンク、写真ハッシュ | 1品＝1行。写真1枚に複数品目でも品目ごとに行を分ける |
| 補正 | 補正ID、対象ID、種類（割合／日時／本人以外／取消／置換）、値、元の発言、日時 | 「半分食べた」等。**元の行は書き換えず補正を追記**（履歴が残る） |
| 確認候補 | 候補ID、情報源（PLAUD／ボイスメモ）、録音ID、録音日時、原文引用、話者、推定品目、推定日時、重複候補ID、状態（保留／承認／却下） | PLAUD・ボイスメモ由来。承認されたものだけ「食事」へ |
| 体重 | 日付、体重kg、情報源 | 週1回程度 |
| 設定 | 目標kcal=1800、食塩目標=7.5g未満、1日の開始=06:00、身長・目標体重 | **後から変更可能** |
| 料理マスタ | 料理名、別名、標準量、kcal範囲、食塩、PFC、出典 | 外食の標準値。よく食べる料理から育てる |

**集計日の計算**：`集計日 = (食べた日時 − 6時間) の日付`（Asia/Tokyo）。
例：10/18 02:00 のラーメン → 10/17 分。10/18 05:59:59 まで 10/17 分。過去の行は削除しない。

### 4-3. 栄養計算のルール

1. **市販品**：商品名・栄養成分表示が分かればそれを優先（確信度A）。
2. **食材・定番料理**：日本食品標準成分表（八訂）と料理マスタの標準量から計算（確信度B）。
3. **外食・写真**：一般的な分量から推定。**単一の数字にせず範囲**（例 カツ丼 850〜1,100kcal、目安950）を保存（確信度C）。
4. **情報不足**：範囲を広く取り確信度D。「推定値です」を必ず表示。
5. **食塩**：1食で3g以上、または1日の目安7.5gを超えそうなときに注意喚起（ラーメン・丼・漬物・つまみ類）。
6. **医療診断ではない**旨を回答・ノートに明記。

※ 日本食品標準成分表の利用条件（出典表示など）は実装時に文部科学省の掲載ページで確認してから取り込みます（現時点では未確認）。

### 4-4. 重複防止

| 状況 | 判定 | 処理 |
|---|---|---|
| 同じ写真を2回送った | 写真ハッシュが一致 | 自動で2件目を登録しない |
| 写真12:05「ラーメン」＋PLAUDで「昼にラーメン食べた」 | 同じ集計日・±90分以内・料理が同系統 | **重複候補**として確認候補に入れ、自動統合しない |
| 「これ半分食べた」 | 直前（3時間以内）の写真記録への補正 | 新規登録せず補正シートに追記。対象が2件以上あり得る時は確認 |
| 判断が曖昧 | — | 自動統合せず確認 |

### 4-5. PLAUD・ボイスメモの扱い（自動確定しない）

- 「食べた／飲んだ／〇杯／〇本」等を含む箇所を原文で抽出。
- 判定項目：本人の発言か（話者ラベルだけで本人と断定しない）、実際に食べたか（予定・冗談・他人の話を除外）、日時が分かるか、既存記録と重複しないか。
- 日時は **PLAUD の録音開始時刻（UTC→JST変換）を基準**にし、Drive のファイル更新日時は使わない。
- 全件「確認候補」として食事DBの「確認候補」シートに入れる（自動確定しない）。
- 「今日の食事」の返答に「候補1 10/16 焼き鳥5本（PLAUD）」のように番号付きで表示し、
  JPが音声で **「候補1は記録」「候補1は不要」** と言うだけで処理する（Todoist は使わない）。
- 既存の録音整理ジョブは読むだけで変更しない（食事ジョブが独立して PLAUD を読む）。

## 6. セキュリティ

- Make Webhook は**APIキー（ヘッダー認証）付きの新規Webhook**にする（既存のAI取込用Webhookは認証なしのため流用しない）。キーはショートカット内にのみ保存し、GitHub・Obsidianには書かない。
- 食事・体重データは業務フォルダと分け、Obsidian では `sensitivity: 機密` とタグを付け、事業ハブ・月別ハブにはリンクしない。
- 外部AIに送るのは写真・食事の文面のみ（氏名等は送らない）。PLAUD の会話全文は外部AIに送らず、Claude 定期ジョブ内で処理する。
- 定期ジョブの書き込み権限は「食事・健康管理フォルダへの新規作成」「食事DBへの追記（確認候補）」に限定。削除は一切しない。
- GitHub リポジトリは公開。コードに個人の健康情報・Webhook URL・合言葉を書かない（実際の値は Drive の食事DB・Make 側にだけ置く）。
- Make の処理コードは GitHub の**コミットを固定した URL** から読み込む（既存ジョブと同じ方式。後から改ざんされても固定したコミット以外は実行されない）。
