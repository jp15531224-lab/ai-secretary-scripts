## 2026-10-22 の点検結果

- API（ウェブアプリ）は稼働中。register / update / roster / history / people / candidate_add / candidates / candidate_confirm がすべて正常に応答。
- 重複防止：同じ人×同じ回の再登録は `duplicate=true` で弾かれ、行は増えない。確認待ち候補も同じ資料・同じ人なら増えない。
- 講師が同じで回が複数ある時は `needs_confirmation` で選択肢を返し、勝手に登録しない。
- **一覧に2026年10月の回が0件**（スクショ取り込みは11月以降のみ）。10/22 加古川・又吉・BE は一覧に無いため、正しく呼べても `seminar_not_found` になる。
- 「このチャットから登録機能を呼び出せない」はAPIのエラーではなく、ChatGPT側の会話に `seminarApi`（action付き v1.1.0 スキーマ）が付いていない時の文言。

## ChatGPT側の設定（JPの作業、約5分・パソコンで）

スプレッドシートの「ChatGPT設定」B4・B5は、プログラムより古い版のまま（B5にボイスメモ読み取り memos が無い）。
指示文の改善は `参加者管理.gs` に組み込んだので、次の手順で B4・B5 を作り直してから GPT に貼る。

1. スプレッドシート →「拡張機能」→「Apps Script」→ 左の「参加者管理.gs」を開く。
2. 中身を全部消して、GitHub の最新 `参加者管理.gs` を貼って保存（https://raw.githubusercontent.com/jp15531224-lab/ai-secretary-scripts/add-zenkosai-seminar-list/参加者管理.gs を開いて全選択→コピー）。「コード.gs」は触らない。
3. 左の「コード.gs」を開き（関数の選択欄は開いているファイルの関数しか出ないため）、上の関数選択で **chatgptSettings** を選んで「実行」。B4（指示）と B5（スキーマ）が新しくなる。
   - デプロイのやり直しは不要（変わったのは指示文を作る部分だけで、台帳の動きは変わらない）。
4. ChatGPT → セミナー用GPT →「編集」→ 指示を全部消して **B4** を貼る。
5. アクション → スキーマを全部消して **B5** を貼る（認証：なし）。下の一覧が `seminarApi` 1つならOK。
6. 「更新」で保存し、そのGPTの文字入力で「動作テスト太郎の履歴を見せて」→ 11/23 又吉BT が返れば接続成功。

※ スキーマには合言葉が入るため、このリポジトリ（公開）の `schema.json` は伏せ字の参考用。貼るのは必ずB5から。
※ `instructions_v1.3.txt` は B4 に出来上がる指示文と同じ内容（確認用）。

## 音声モードについて

- アクション（seminarApi）が呼べるのは、そのGPTの会話の中だけ。通常のChatGPTの会話からは呼べない。
- GPTの中で音声モードからアクションが呼べるかは、ChatGPTの仕様変更が多く、ここからは検証できない（不明）。
- 確実な方法：GPTの会話で、入力欄の**マイク（音声入力）ボタン**で話す。文字として送られるので、テキストと同じ経路で必ず登録できる。

## 参加者の増減の自動化（2026-10-23 追加・指示文 v1.3）

ChatGPTに「山田さんを追加して」「田中さんが来られなくなった」「佐藤さんがやっぱり参加する」「山下さんを外して」と話すか、
LINEの文章・名簿を貼るだけで台帳が更新される。Claude Codeの操作は不要。

| action | 用途 | 主な項目 |
|---|---|---|
| apply | 追加・不参加・再参加・判断できない人をまとめて処理 | join / leave / undecided（「、」区切り）, reason, source_type, source_ref |
| roster_sync | 名簿との照合 | names（全員）, complete=true は最新の完全な名簿とJPが確認した時だけ |
| changes | 変更履歴 | name / seminar_id |
| person_rename | 氏名の訂正（参加記録の氏名も直す） | name か person_id, new_name |

- 不参加は「キャンセル」（参加予定だった人）か「辞退」（返事前だった人）で保存。行は消さない。
- 「変更履歴」シートに、変更前・変更後・日時・理由・出典を1件ずつ残す（登録・状態変更・氏名訂正すべて）。
- セミナー指定なしの leave は、本人の今後の予定が1件ならそれを対象にする（複数なら選択肢を返す）。join は直近24時間に扱ったセミナー。
- 判断できない人・名前が確定しない人・同名が複数いる人・参加済みの人の不参加は「確認待ち候補」へ（参加記録は変えない）。
- complete=false（既定）の名簿照合では、名簿に名前が無いだけの人は不参加にしない（not_in_list_kept に出る）。
- complete=true でも、参加予定の半分以上（3人以上）が一度に不参加になる時は mass_leave で確認を求める（force=true で実行）。
- 書き込みはすべて「書く→読み直して全列一致を確認→合わなければ同じ行に最大3回書き直す」。結果は応答の sync（ok / writes / verified / retries / errors）。
- 書き込み系は排他ロック。混んでいる時は何も書かずに busy を返す（ChatGPTが1回呼び直す）。
- 同じ人×同じ回は1行だけ（register で状態を変えて再登録した場合も、行を増やさず状態を変更）。

### 見つけて直した不具合

- 確認待ち候補「山下」を承認した時に、人物・参加記録の氏名が「P山」で保存されていた（10/23 09:21）。承認時に渡された名前がそのまま保存されたのが原因で、名前の妥当性確認が無かった。→ 英字＋漢字の混入やIDの貼り間違いを名前として受け付けないようにし、person_rename で訂正できるようにした。
- register で、キャンセル済みの人を再び参加予定にしようとしても duplicate で止まり、状態が変わらなかった。→ 状態を指定した再登録は、同じ行の状態変更として扱う（履歴あり）。
- 書き損じの再試行で新しい行を追加してしまう可能性があった（新設の検証処理のテストで発見）。→ 1回目に書いた行を覚えて同じ行に書き直す。
