## （参考・保留）ChatGPT側からMake経由で呼ぶ構成

ChatGPT では「設定 → プラグイン」に登録済みの **「全厚済セミナー台帳」** を使う。カスタムGPTは作らない・編集しない。

```
ChatGPT「全厚済セミナー台帳」 → Make ツール（シナリオID 8111196） → Apps Script ウェブアプリ（ChatGPT設定 B1 のURL） → スプレッドシート
```

- ChatGPT が見る「使い方」は、Make ツールの**説明文と入力欄の説明**（シナリオ 8111196 の interface）。スプレッドシートの「ChatGPT設定」B4（指示）・B5（スキーマ）は**プラグインには反映されない**（カスタムGPT用の参考として残しているだけ。貼る作業は不要）。
- Make → Apps Script の合言葉は Make のモジュール内に保存（リポジトリには載せない）。ChatGPT → Make の認証は ChatGPT 側の接続設定による（ここからは見えない）。
- Apps Script を直した時は「デプロイを管理 → 新バージョン」だけで、プラグインにもそのまま反映される（URL が変わらないため）。
- **新しい項目（パラメータ）を足した時だけ**、Make ツールの入力欄（inputs）と送信項目（qs）にも同じ名前を追加する。追加しないと Make が「Unexpected parameter」で止める。
- ChatGPT 側で新しい入力欄が見えない時は、ChatGPT の設定でプラグインを開き直す／新しいチャットで試す（ChatGPT の画面はここから確認できないため、具体的な操作は不明）。

## 音声モードについて

- アクション（seminarApi）が呼べるのは、そのGPTの会話の中だけ。通常のChatGPTの会話からは呼べない。
- GPTの中で音声モードからアクションが呼べるかは、ChatGPTの仕様変更が多く、ここからは検証できない（不明）。
- 確実な方法：GPTの会話で、入力欄の**マイク（音声入力）ボタン**で話す。文字として送られるので、テキストと同じ経路で必ず登録できる。

## 参加者の増減の自動化（2026-10-23 追加・指示文 v1.3）

ChatGPTに「山田さんを追加して」「田中さんが来られなくなった」「佐藤さんがやっぱり参加する」「山下さんを外して」と話すか、
LINEの文章・名簿を貼るだけで台帳が更新される。Claude Codeの操作は不要。

| action | 用途 | 主な項目 |
|---|---|---|
| apply | 追加・不参加・再参加・判断できない人をまとめて処理 | join / leave / undecided（「、」区切り）, reason, source_type, source_ref |
| roster_sync | 名簿との照合 | names（全員）, complete=true は最新の完全な名簿とJPが確認した時だけ |
| changes | 変更履歴 | name / seminar_id |
| person_rename | 氏名の訂正（参加記録の氏名も直す） | name か person_id, new_name |

- 不参加は「キャンセル」（参加予定だった人）か「辞退」（返事前だった人）で保存。行は消さない。
- 名簿で（）付きのグループリーダーは、状態「リーダー（不参加）」で記録（参加人数・連絡リストに入らない。後で join すると「追加」で参加予定になる）。
- 名簿の書き方のルール（JP指定 2026-10-24）
  - （）付きの名前＝参加しないグループリーダー → 「リーダー（不参加）」。括弧が無ければリーダーも参加（参加予定）。
  - 名前の後ろの ◯○〇⚪＝新規・あまりセミナーに行っていない人、◎＝未登録新規（new_kind で区別、どちらも is_new=true）。印は氏名から外し、参加記録の「印」列に残す（`is_new=true`）。※⭐ などの他の印も「印」列に残すが新規扱いにはしない。
  - apply / roster_sync の join・names には名簿の書き方のまま（括弧・印つき）渡してよい。サーバー側で読み分ける。
  - roster は各参加者に mark・is_new を返し、attending・new_attending・leaders も返す。sort=new で新規を先頭、new_only=true で新規だけ。PDFにも「新規」列。
- 「変更履歴」シートに、変更前・変更後・日時・理由・出典を1件ずつ残す（登録・状態変更・氏名訂正すべて）。
- セミナー指定なしの leave は、本人の今後の予定が1件ならそれを対象にする（複数なら選択肢を返す）。join は直近24時間に扱ったセミナー。
- 判断できない人・名前が確定しない人・同名が複数いる人・参加済みの人の不参加は「確認待ち候補」へ（参加記録は変えない）。
- complete=false（既定）の名簿照合では、名簿に名前が無いだけの人は不参加にしない（not_in_list_kept に出る）。
- complete=true でも、参加予定の半分以上（3人以上）が一度に不参加になる時は mass_leave で確認を求める（force=true で実行）。
- 書き込みはすべて「書く→読み直して全列一致を確認→合わなければ同じ行に最大3回書き直す」。結果は応答の sync（ok / writes / verified / retries / errors）。
- 書き込み系は排他ロック。混んでいる時は何も書かずに busy を返す（ChatGPTが1回呼び直す）。
- 同じ人×同じ回は1行だけ（register で状態を変えて再登録した場合も、行を増やさず状態を変更）。

### 見つけて直した不具合

- （訂正）10/23 に「P山」を誤記と判断して「山下」に直したが、JPは「P山」「石原GM」「東谷け」のような呼び名で登録しており、P山は正しい名前だった（ChatGPTアプリ側の台帳で P山 と 山下け が別人として登録されていた）。→ 英字＋漢字を弾くチェックを外し、氏名は元の「P山」に戻す（変更履歴に両方の操作が残る）。
- register で、キャンセル済みの人を再び参加予定にしようとしても duplicate で止まり、状態が変わらなかった。→ 状態を指定した再登録は、同じ行の状態変更として扱う（履歴あり）。
